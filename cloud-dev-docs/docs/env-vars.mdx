# Environment Variables

All configurable environment variables live in `compose.yaml` under the **dev** service. The init script writes them into `/config` on every boot, so they take effect immediately.

`AGENT_API_KEY` (or the per-agent key below) is the only value you must provide: without it, the agent will prompt for auth on first run. Every other variable falls back to the default shown in its table.

## How it works

```
compose.yaml          init.sh              /config/.bashrc
(dev service)     →   writes vars  →      /config/.zshrc
```

Edit `compose.yaml`, recreate the container, done.

## Agent Selector

| Env var | Default | What it does |
|---------|---------|---------------|
| `AGENT` | `claude` | Which coding agent to install and auto-launch: `claude`, `codex` or `cline` |
| `AGENT_API_KEY` | *(empty)* | Generic API key, mapped to the selected agent. Per-agent keys take precedence if set |
| `AGENT_MODEL` | *(empty)* | Generic model override for the selected agent. Leave empty for the agent default |
| `AGENT_BASE_URL` | *(empty)* | Generic base URL override (Claude Code only; unsupported by Codex) |
| `CODEX_VERSION` | `0.160.1` | Pinned Codex CLI version. Set to `latest` to opt out of version pinning |

**Codex example:**

```yaml
AGENT: codex
AGENT_API_KEY: sk-...   # your OpenAI API key
AGENT_MODEL: gpt-5      # optional, leave empty for Codex default
```

**Cline example:**

```yaml
AGENT: cline
AGENT_API_KEY: sk-ant-...  # your provider key (Anthropic by default)
CLINE_PROVIDER: anthropic  # e.g. anthropic, openai
```

Then on first login run `cline auth` (interactive, persists in `/config/.cline`). Env keys are convenience only — Cline's `providers.json` is IDE-managed, so headless API-key-only setup is best-effort. Per-run flags also work: `cline -P anthropic -m <model> -k <key> "task"`.

> NOTE: merge pre-seed into `providers.json` is implemented in `init.sh` but UNTESTED against a real Cline binary. Before claiming zero-touch BYOK: boot with `AGENT=cline`, confirm `cline` picks up the pre-seeded provider without prompting, and check with maintainers which providers accept `apiKey` in settings vs OAuth-only.

Or use the per-agent key instead of the generic one (`OPENAI_API_KEY: sk-...` for Codex, `ANTHROPIC_AUTH_TOKEN` for Claude, `CLINE_API_KEY` for Cline).

## Claude Code / API

| Env var | Default | What it does |
|---------|---------|---------------|
| `ANTHROPIC_BASE_URL` | *(empty)* | Leave empty for Anthropic. Set to a third-party URL ([DeepSeek](https://platform.deepseek.com), [OpenRouter](https://openrouter.ai), etc.) to use a different provider |
| `ANTHROPIC_AUTH_TOKEN` | *(required)* | Your API key. Get one at [console.anthropic.com](https://console.anthropic.com) |
| `ANTHROPIC_MODEL` | `claude-opus-4-8` | Default model Claude Code uses for all tasks |
| `ANTHROPIC_DEFAULT_OPUS_MODEL` | `claude-opus-4-8` | Model used when Opus tier is selected |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | `claude-sonnet-4-6` | Model used when Sonnet tier is selected |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | `claude-haiku-4-5` | Model for Haiku tier (lighter tasks, subagents) |
| `CLAUDE_CODE_SUBAGENT_MODEL` | `claude-haiku-4-5` | Model for background agents spawned by Claude Code |
| `CLAUDE_CODE_EFFORT_LEVEL` | `max` | Reasoning depth: `low`, `medium`, `high`, or `max` |

### Using a different provider

If `ANTHROPIC_BASE_URL` is left empty, Claude Code connects directly to Anthropic's API. To use a third-party provider, set the URL and adjust model names.

**DeepSeek example:**

```yaml
ANTHROPIC_BASE_URL: https://api.deepseek.com/anthropic
ANTHROPIC_AUTH_TOKEN: sk-...       # your DeepSeek key
ANTHROPIC_MODEL: deepseek-v4-pro[1m]
ANTHROPIC_DEFAULT_HAIKU_MODEL: deepseek-v4-flash
CLAUDE_CODE_SUBAGENT_MODEL: deepseek-v4-flash
```

**OpenRouter example:**

```yaml
ANTHROPIC_BASE_URL: https://openrouter.ai/api/anthropic
ANTHROPIC_AUTH_TOKEN: sk-or-v1-... # your OpenRouter key
ANTHROPIC_MODEL: anthropic/claude-opus-4-8
```

### How to apply changes

Edit `compose.yaml`, recreate the container:

```bash
docker compose up -d --force-recreate
```

Or, for a quick test without recreating:

```bash
nano ~/.zshrc
source ~/.zshrc
```

## Git / GitHub

| Env var | What it does |
|---------|---------------|
| `GIT_USER_NAME` | Your name for commits (`git config user.name`) |
| `GIT_USER_EMAIL` | Your email for commits (`git config user.email`) |
| `GITHUB_TOKEN` | GitHub [fine-grained PAT](https://github.com/settings/tokens?type=beta), used by both `git` (via `gh` credential helper) and the `gh` CLI |

### Creating a GitHub token

Go to [github.com/settings/tokens?type=beta](https://github.com/settings/tokens?type=beta):

1. **Repository access**: "Only select repositories", pick which ones
2. **Permissions**: Contents (read/write as needed), Metadata (read, auto-selected)
3. Copy the `github_pat_...` token into `GITHUB_TOKEN`

The token can be revoked or scoped anytime. No account password stored: if the container is compromised, you only lose access to the repos you explicitly granted.

After setting these and recreating the container, both `git clone`/`push`/`pull` and `gh` CLI commands (`gh pr`, `gh issue`, etc.) use the token automatically.

## Session behavior

These variables are **not** set in `compose.yaml`. They are passed at connection time (by your SSH client or in the shell) to control what happens when you log in.

| Env var | Default | What it does |
|---------|---------|--------------|
| `NO_AGENT` | *(unset)* | Set to `1` to skip agent auto-launch and get a plain shell (`NO_CLAUDE=1` still works as an alias) |
| `TMUX_AUTO` | *(unset)* | Set to `1` to auto-attach a persistent tmux session on login |
| `TMUX_TIMEOUT` | *(unset)* | Hours before a detached tmux session is auto-killed (`-1` = never, `0` = on detach, `N` = after N hours) |

### Agent auto-launch

The selected agent (`AGENT`) launches automatically on every login (both SSH and web terminal). You land in `/workplace` with the agent ready. Exiting the agent (`/exit` or `Ctrl+D`) returns you to a normal shell prompt.

To skip the auto-launch:

```bash
NO_AGENT=1 ssh abc@<server> -p 2222    # → plain shell, no agent
```

### Persistent sessions with tmux

Set `TMUX_AUTO=1` on your SSH client (e.g. Termius environment variables) to wrap every session in tmux. When you disconnect, tmux keeps running. When you reconnect, you reattach to the same session with the agent still there.

```bash
# In Termius: set TMUX_AUTO=1 in the host's environment variables
# In a terminal:
TMUX_AUTO=1 ssh abc@<server> -p 2222    # → auto-attached to tmux "main"
```

Use `TMUX_TIMEOUT` to auto-clean detached sessions. For example, `TMUX_TIMEOUT=2` kills sessions that have been detached for more than 2 hours. Run `tmux-keep` inside a session to override this and keep it alive indefinitely.

See [Daily Workflow](./daily-workflow) for full tmux usage.

## Webhook Notifications

When the agent finishes responding and waits for input (60+ seconds idle), a webhook can fire if no one is connected to the container. This is useful for long-running tasks: start the agent inside tmux, disconnect, and get notified when the agent is ready for your next prompt.

Claude uses its built-in `idle_prompt` Notification hook (precise). Other agents (e.g. Codex) use a generic tmux-silence watcher. No extra setup required.

| Env var | Default | What it does |
|---------|---------|---------------|
| `AGENT_WEBHOOK_URL` | *(empty)* | Webhook endpoint URL. Leave empty to disable. Receives a JSON POST when the agent goes idle with no active connections (`CLAUDE_WEBHOOK_URL` still works as an alias) |
| `AGENT_WEBHOOK_IDLE` | `60` | Seconds of terminal silence before the agent is considered idle (minimum 60) |

### Webhook payload

```json
{
  "event": "claude_idle",
  "agent": "claude",
  "timestamp": "2026-07-24T15:30:00Z",
  "hostname": "claude-world",
  "session_id": "35e6a910-...",
  "last_output": "The fix has been applied to utils.py.\n\nAll tests pass.\n\n> What should I do next?"
}
```

| Field | Description |
|-------|-------------|
| `event` | Event name: `"<agent>_idle"` (e.g. `"claude_idle"` or `"codex_idle"`) |
| `agent` | Selected agent name (`"claude"` or `"codex"`) |
| `timestamp` | UTC ISO 8601 timestamp |
| `hostname` | Container hostname |
| `session_id` | Claude session ID that triggered the hook, or `"<agent>:<pane>"` for the generic watcher |
| `last_output` | Last text output from the agent (up to 2000 characters) |

### How it works

1. You connect via SSH or web terminal, the agent auto-launches
2. You give the agent a task, it starts processing
3. You disconnect (tmux keeps the agent running if `TMUX_AUTO=1`)
4. The agent finishes the task and waits for input
5. After 60 seconds of idle (Claude fires its `idle_prompt` hook; other agents are detected by the tmux-silence watcher)
6. The sender checks `who` for active connections
7. If no one is connected, it sends the webhook with the agent's last output

The webhook can point to any HTTP endpoint: Slack webhooks, Discord webhooks, Telegram bots, Zapier, n8n, ntfy, or a custom server.
